- **Count-drift discipline**: every "N decorators / N diagnostics" claim in docs should be generated or checked in CI (a tiny test asserting `extern dec` count and `$lib.diagnostics` key count against constants in README/AGENTS would make drift impossible).

- **Probe hygiene**: one-directory probes (`scripts/probe-*`) invite accidental commits. Use `/tmp` or a gitignored `scratch/`.
- **Design decisions made silently**: `@jsonSchemaExtension`/`@extension` merge semantics ("outermost same-key wins") was derived from decorator execution order and baked into tests+docs without asking. Defensible, but it's public-API surface — should have been surfaced at review time.
- **Test names must not overclaim**: P2/P5 names promise stronger checks than their assertions deliver. Either strengthen the assertions or soften the names; a reader trusting names would over-estimate coverage.
- **Verify loop cost**: each task cost 2–4 full verify runs (~4 min each) due to lint/clone surprises late in the loop. Pre-flight `lint:eslint && duplicate` on the touched files would have halved wall time.
