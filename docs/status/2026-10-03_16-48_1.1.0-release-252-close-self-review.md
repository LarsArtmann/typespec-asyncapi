## e) WHAT WE SHOULD IMPROVE

1. **Non-empty guard on publish flows** — `test -s body.md &&` before every
   `gh` body-file call; a silent-empty file is one quoting bug away from a
   blank public comment (this time GitHub saved us; a blank body that
   VALIDATES would not be saved).
2. **Lockfile drift checks must target the root importer block**, not
   whole-file version greps (website's TS 7 is legitimate). Encode the
   snippet in AGENTS.md.
3. **Never tick before the verify command returns.** TODO/report claims
   follow evidence, always.
4. **Bake the propagation wait into the release ritual** — after publish,
   one poll at +3 min, not immediate multi-probing.
5. **When a tool is security-blocked (systemctl/crontab), read the unit
   files directly** (`~/.config/systemd/user/`, `/etc/cron.d/`,
   `~/.local/bin` scripts). Untried this session; would likely have named
   the auto-writer.
6. **Atomic release protocol under a racing auto-writer** — restore →
   commit → tag → push in ONE command chain. It worked; document it as THE
   ritual in AGENTS.md so the next release doesn't re-derive it.
7. **Check `--help` before exotic gh flags** (`--comment-file` was
   invented).
8. **Draft file convention** — a separate body file (or a `<!-- body -->`
   marker) would remove the header-stripping awk entirely.
