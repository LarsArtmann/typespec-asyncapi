One-paragraph state

v1.0.0 was tagged, published with provenance (sigstore logIndex 3009748579), given a GitHub release, and verified end-to-end from a clean registry install whose output AJV-validates against the official AsyncAPI 3.1.0 schema. DTotally Fucked Up

Master CI was red for 5½ days and nobody knew

What: every CI run on master since 2026-09-24 22:32 UTC failed (5 consecutive runs) — the Dependabot "21 updates" PR failed its own CI check (frozen-lockfile mismatch) and was merged/committed to master anyway (d83d1cf8); every daemon push after that kept failing.
Severity: process-critical. The 1.0.0 tag was pushed onto a tree whose CI was red; only the release workflow's own verify run caught it (the most expensive possible place).
Root cause: no branch protection requiring green CI + no one monitoring master CI + the auto-commit daemon merges whatever is on disk.
Mitigation: lockfile now regenerated; master CI green as of 01:48 UTC (run on 5c89244d's parent). Fix is content, not process — see E/F for the durable fix.

Un-gated toolchain drift reached the release tag

What: typescript ^7.0.2 and 7 dev-dep bumps landed via an auto-commit (c4de6190, 151 files) that never ran the gate; a local "green" verify was measuring a stale node_modules — a different dependency set than CI installs.
Severity: high — "pnpm run verify green" locally was not evidence about what CI would do.
Root cause: stale node_modules masked manifest drift; nothing validates manifest↔lockfile↔node_modules coherence before tagging.
Mitigation: documented preflight (install --lockfile-only → frozen install → verify) in AGENTS.md; not yet automated.

Dependency pins now block the upgrade path (deliberate debt)

What: typescript held at ^6.0.3 and typescript-eslint at 8.70.x because 8.71+ hard-blocks TS 7 (typescript-eslint#10940). Dependabot will keep re-offering bumps that break the gate until upstream ships TS 7 support.
Severity: medium — every future dep-bump PR risks another red CI cycle; ESLint plugin stays a minor behind.
Root cause: upstream (typescript-eslint TS 7 support), timing unknown.
Mitigation: pins documented in AGENTS.md + TODO with the revisit condition; declining the bumps is correct until then.

npm token cannot delete dist-tags (403) and "set" 400s

What: npm dist-tag rm … alpha → 403 Forbidden; npm dist-tag set … beta 1.0.0 → 400 Bad Request; only npm dist-tag add works.
Severity: low (cosmetic tag), but symptomatic of token scope/restriction drift — the same token class npm is deprecating for 2FA-bypass publishing.
Root cause: unknown — needs the token rotation to also review scopes.
Mitigation: alpha removable via npmjs.com UI.

EWhat We Should Improve

  • Branch protection on master requiring green CI. Today a failed Dependabot PR merged anyway. Impact: the entire 5½-day red window. Fix: GitHub settings, 10 minutes.
  • A one-command release preflight (scripts/release-preflight: lockfile-only → frozen install → verify → clean-tree check). The manual sequence worked tonight but lives only in AGENTS.md prose. Impact: prevents the most expensive failure mode (red tag push).
  • Gate the auto-commit daemon on toolchain files. package.json/tsconfig/lockfile changes should trigger at least a build before commit. Impact: prevents the next ^7.0.2-style drift.
  • Watch typescript-eslint#10940 and un-pin deliberately when TS 7 support lands (typescript-eslint AND typescript together, one PR). Impact: restores the upgrade path.
  • Announce releases. 1.0.0 shipped hours ago with zero external signal; the XYD thread has been quiet since 08-21. Announcement discipline is the cheapest adoption lever we are not pulling.
  • Verify README's competitive table at install-time (the tsp-asyncapi comparison row) before claiming it in the announcement.
  • Same improvement now in 2+ sessions: false-green local gates. Candidates for a skill/hook: preflight enforcement.
