05Claims Investigated and Dismissed

"mutualTLS is a valid AsyncAPI 3.1 scheme type — the emitter allowlist is wrong"

Agent finding, plausible (OpenAPI 3.1 has it). Verified against the official AsyncAPI 3.1.0 JSON schema in @asyncapi/specs/schemas/3.1.0.json: mutualTLS does not appear anywhere in the schema. The emitter allowlist is correct; the rejection test is correct. Dismissed with evidence.

"@encode tests assert wrong serialization"

Two of three flagged tests are named "does not break X" — asserting native passthrough is exactly their contract. Only the third name overclaimed; renamed. The emitter's passthrough-vs-encode semantics remain worth a deliberate decision (harvested).

06Decision Resolved: Locked In

BEHAVIOR CHANGE · RESOLVED

Named unions now emit @doc / @summary metadata

src/schema-emitter.ts (commit 7f6c9b1, mapUnionVariants dedup)

Before: named unions silently dropped @doc/@summary. After: they emit description/title like every other declaration. No test ever pinned the old behavior. The follow-up session locked the new behavior in as public contract: a "named union metadata propagation" suite in test/compliance/polymorphism.test.ts asserts description from @doc and title from @summary alongside oneOf. Consistency with enums and scalars (same declareSchema path) won over byte-compat with an unpinned behavior.
